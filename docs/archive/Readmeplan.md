### Important generation rules

Put these instructions **at the top of the prompt that generates the README**:

```md
## README Generation Rules

1. Use `BhoomiSetu_Master_Project_Document.md` as the single source of truth.

2. Read the entire master document before generating the README.

3. Do not invent, assume, hallucinate, or introduce project details
   that are not supported by the master document or actual repository.

4. Preserve all important numerical data, technical specifications,
   workflows, architecture decisions, requirements, and constraints
   documented in the master document.

5. If two sections of the master document contain different versions
   of the same information, use the latest explicitly documented
   decision.

6. Clearly distinguish:
   - Implemented
   - Planned
   - Proposed
   - Future Scope
   - Prototype / Demonstration functionality

7. Do not present planned functionality as implemented functionality.

8. Do not expose API keys, passwords, tokens, secrets, or credentials.

9. Do not expose `.env` values. Only document variable names and their
   purpose.

10. Use Mermaid diagrams where they improve readability.

11. Generate architecture diagrams from the actual architecture
    documented in the master document.

12. Generate workflow diagrams from the documented workflows.

13. Generate tables wherever structured information improves clarity.

14. Do not duplicate large explanations unnecessarily.

15. Keep the README technically accurate and suitable for:
    - SIH judges
    - Developers
    - Evaluators
    - Project reviewers
    - Future contributors

16. The README should explain both WHAT the system does and HOW it
    works.

17. Every major claim must be traceable to the master document.

18. Do not remove important problem-statement information merely to
    make the README shorter.

19. Do not add marketing claims such as "revolutionary", "best",
    "world-class", "100% secure", or "production-ready" unless such
    claims are explicitly supported.

20. The final README must reflect the current implementation and
    architecture, not an idealized version of the project.
````

This gives you a **format/schema**, while the actual content is pulled from the master document and, where necessary, verified against the repository.
